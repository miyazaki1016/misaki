# 通常会話の外部情報セレクタ V1（オフライン実験・2026-10-22）

## 今回の実装範囲
隔離実験ブランチ `experiment/chat-input-metrics-offline-20261022` に
- `lib/conversation-engine/chat-external-relevance.ts`
- `tests/chat-external-relevance-offline.test.ts`
を追加した。これは**純粋関数の最小プロトタイプ**で、現在のMisakiの会話処理やBody Clockには接続していない。APIの定期取得、プッシュ、Gemini、Supabase、課金処理は行わない。

## 動作上の設計
- 発言から区別済みのトピック（smalltalk/weather/earthquake/transport/other）と、認可・検証・鮮度・地域適合済みの外部情報候補を入力する。
- 選別条件の優先順位は、利用権→確認済み情報→鮮度→地域適合→高重要度の関連イベント→質問トピックとの一致。
- 挨拶では、通常天気や羽田・東京の鉄道情報を入力しない。天気を聞かれた時は許可された地域の天気候補のみ。
- 対象地域で確認できた高重要度の地震・気象警報は、通常会話の文脈候補として利用可能。ただし、**これは自発メッセージの送信判断でも送信許可でもない**。
- 各候補の採用/不採用と理由コードを返す。ソース名/情報全文はログ化しない。
- 現在地・居住地・ユーザー職業からの地域推定は、この部品では一切行わない。入力する`relevantRegion`の認証/検証は別ゲートの責任。

## 今回追加の合成テスト（7ケース、現時点では未実行）
1. 雑談で通常天気・羽田・鉄道は不要
2. 天気質問では天気のみ
3. 交通質問でも地域外・期限切れの羽田は採用不可
4. 地震の重要度が高くても利用権がなければ不採用
5. 地域に関係する高重要度地震は通常会話の候補にできるが配信しない
6. 未確認または期限切れの地震を採用しない
7. 同じイベントIDを重複処理しない
