# 東京イベント取得の全段階統合計画（オフライン設計）

## 判定順序

1. 気象庁feedの取得結果（成功／失敗）を独立して記録する。
2. 成功したfeedについてXML構造の互換性を検査する。構造異常なら「正常に情報なし」としない。
3. 一覧から抽出した候補IDと、選別理由（対象／対象外／リンクなし／上限到達）を照合する。
4. 選別された候補IDと詳細取得IDを一致させ、成功・失敗・スキップを確認する。
5. 地震・警報以外も含めて取得元の状態を集計し、どこかに未確認・失敗・スキップがあれば全体の完全性を保証しない。

## 現時点の注意点

- XML構造の正規表現検査は完全なXMLパーサーではない。構造が正常でも候補抽出の正しさを保証しない。
- 現行の取得処理は通信失敗をnull、その後空配列に変換するため、状態の観測はfetchの戻り値を捨てる前に行う必要がある。
- 取得件数の上限到達は製品仕様として正常でも、全件確認済みと同義ではない。
- 本計画は設計のみ。実fetch・プロンプト・main・本番・Supabase・有料APIは未変更。Nodeテストと実データ検証は未実施。
