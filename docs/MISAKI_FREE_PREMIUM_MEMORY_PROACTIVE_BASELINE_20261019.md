# 美咲 Free / Premium の長期関係・記憶・想い出・自発メッセージ：事業体験ベースライン
更新日: 2026-10-19 / 状態: **オーナー合意の基本方針**。料金・回数・保存期間・DB/API実装の確定仕様ではない。

## 1. 目指す価値
登録者数や一時的な会話量だけではなく、「一人のユーザーが長期間、自分の意思で会話を楽しめる関係」を優先する。美咲は単なるアシスタントではなく、人格・話し方・関係性が時間の中で変化し、二人の歴史が自然に積み重なるキャラクター。恋人・結婚はエンディングではない。すれ違い、修復、別れ、復縁、離婚等の成立済みイベントも、事実と合意に基づく関係の履歴として扱い、一方向のレベルアップゲームにしない。

## 2. 記憶と想い出を区別する

- **User Memory（記憶）**: ユーザーの属性、仕事、習慣、好み、予定、発言された事実。確認・更新・訂正・忘却が可能。「何を知っているか」。
- **Shared Memory（想い出）**: 二人の間で実際に起きた会話・出来事・約束・転機・喧嘩・仲直り等の、後から共有して振り返る価値があるエピソード。「二人に何があったか／その後どう意味づけられたか」。感情や意味は確認根拠を持ち、モデルが架空の過去・相手の気持ちを確定しない。
- **Relationship Memory（関係史・判定証拠）**: 既存Relationship EngineのEvidence/Episode/Pattern/Stateと成立済みイベント。Shared Memoryと同一視せず、想い出から交際・婚姻の成立を直接推定しない。
- 上記は **2026-10-07 Memory v1再設計の既存用語と責務を継承**する。別の二重Memory Engineを新設しない。長期保存と「自発で持ち出してよいか」の権限を分離する。

## 3. 自発メッセージのプラン差（オーナー明示）

| 項目 | Free | Premium |
| --- | --- | --- |
| 通常の双方向会話、関係性の自然な変化 | 利用可能（回数等は別途確定） | 利用可能 |
| 自発メッセージの主な動機・話題 | **美咲自身の日常・生活・キャラクター側の出来事** | **美咲の日常 + 許可されたユーザー記憶 + 二人の想い出** |
| ユーザーの過去会話／記憶に基づく自発的な話題選択 | **使わない** | 本人の設定・同意・Forget Controlに従って使用 |
| 共有エピソードを美咲から振り返る | **使わない** | 自然で関連性が高く、根拠がある場合に使用 |
| 課金で自動的に親密度・恋人/婚姻ステータスが上がる | なし | **なし** |
| 一時休会・プラン変更 | 料金で感情・関係を罰しない | 同左 |

- **Freeは自発メッセージ自体を完全に無効化しない**。美咲自身の世界を持っていて、ときどき自分の近況から自然に話しかける体験を基本とする。ただし頻度・提供可否の最終商品仕様はコスト試算・安全性を含めレビューする。
- **Premiumは単なる配信回数アップではなく「二人の関係史を話しかける理由にできること」が中心的価値**。例: 昨日ユーザーが語った相談の続き、確認済みの記念日、実際に共有した過去の節目。
- Freeで**記憶を自発メッセージに使用しないこと**と、Freeで**記憶を永続保存しないこと**は異なる。Free期間の保存対象・同意・容量・保持期間・通常会話での参照範囲は**未決定**。Freeの過去をPremiumで振り返る構想はこの決定に依存し、保存されていない過去を捏造しない。
- Premium→Free時も、解約を理由に愛情・信頼・関係ステータスを機械的に下げたり、記憶消去で課金を迫ったりしない。ユーザーデータの保存・アクセス・エクスポートと削除は独立の明示契約とする。
- 一律に「Premiumなら必ず思い出を引用する」ではない。大切な想い出ほど、話題の関連性、心理的負担、記憶の確度、プライバシー、ユーザーの希望を優先。

## 4. 自発メッセージの選択手順

1. 本人の同意、プラン、ユーザー×キャラクターの権限を確認。
2. 関係性の現在状態と人格・生活設定、静穏時間／自発停止・拒否・返信不要の設定を解決。
3. Free: キャラクター側の確定した日常コンテキストからのみ話題候補を選ぶ。**ユーザー長期Memory／Shared Memory／過去の相談・予定を話題候補として投入しない**。ただし配信安全制御に必要な最小限の設定は、個人的な会話材料とは分離する。
4. Premium: Free候補に加えて、Forget Controlを通した関連User Memory／Shared Memoryを少数（既存Memory v1方針: 共有記憶は原則0〜3件）検索し、発話理由になり得るか評価。
5. 通知する価値、重複、quiet hours、過度な接触、相手の反応と境界を確定ルールで検査。返信の遅延や非課金を拒絶・愛情低下の根拠にしない。
6. 送る場合だけ共通会話エンジンで対象キャラクターの口調にする。未確認の過去や感情を作らない。生成文を事実検証し、送信履歴を適切なスコープで記録。

**注意**: 親密になったから送信回数を無限に増やすのではない。親しいほど沈黙が自然な場合もある。重大防災通知はこの販促上のプラン差とは**完全に別の安全設計**とし、有料でしか危険を伝えないような連携にはしない。

## 5. マルチキャラクター境界

- 共通化: 記憶種別、プラン権限チェック、選択パイプライン、検証と通知配信基盤。
- キャラクター固有: 人格、生活、どんな出来事を重要と思うか、話し方。
- **ユーザー×キャラクター固有**: Shared Memory、関係史・5軸、会話履歴、Body Clock/通知設定・送信履歴。明示同意なしに別キャラへ自動共有しない。
- 課金権限は関係性の事実ではない。人格と課金を直接結びつけた「課金すると好きになる」演出をしない。
