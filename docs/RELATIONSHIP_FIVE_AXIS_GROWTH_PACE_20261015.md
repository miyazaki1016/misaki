# 5軸成長速度のソース照合と理論下限（2026-10-15）

**対象:** main の `lib/relationship-engine-v1.ts`、`lib/relationship-processing-v1.ts` と Draft PR #85のInterpreter実験。これはソースに基づく条件付き計算であり、実ユーザーの平均成長速度の測定ではない。

## 現行の決定規則

1. 直接のユーザー発話で、confidence≥0.8、strength≥50のEvidenceがEpisode候補。会話だけで無条件に点数は増えない。
2. 同じ `type:axis:polarity` について、**別々の東京日付3日**のEpisodeを集めて1Pattern。1日何度発話しても同じ意図のEpisodeは1件。該当Episodeが無ければ進まない。
3. 成立したPatternは原則1点。処理単位の軸別deltaは±3上限。新たなPatternが成立しない限り日付経過だけで増えない。
4. `romantic_declaration` のEpisode keyは日付に関係なく固定されるため、同一宣言タイプの反復だけでは3日Patternを形成しない。

## 1軸につき1日1つの適格Episodeを継続できた場合の「最速」計算

単一 `type:axis:positive` で1日1Episode、負のEvidenceなし、同一軸の他タイプなし、スコア初期値0を仮定。3日で1点、6日で2点……と進む**理論的な最速ペース**（3日目に最初の1点）。日付は暦日であり、連続する利用・Analyzer認定・正本保存・処理成功が全て必要。

| 目標score | 必要な独立Episode日数 | 実験版Interpreterの境界 | コメント |
|---:|---:|---|---|
| 1 | 3日 | 現行/実験とも人格急変なし | 1点の効果は長期scoreより会話履歴・直近文脈に依存 |
| 20 | 60日 | 実験版「少し打ち解ける」 | 毎日認定でも約2か月 |
| 45 | 135日 | 現行romance「少し育つ」 | 恋愛Declarationの反復では達成できない |
| 50 | 150日 | 実験版「自然な親しさ」 | 毎日認定でも約5か月 |
| 80 | 240日 | 現行/実験の高水準表現 | 毎日認定でも約8か月 |

**重要な限定:** これは「1軸に1種類の正のEvidenceタイプが毎日1件」の条件付き計算。同じ軸に異なるtypeの独立Patternが並行成立すれば、1回の処理で最大+3となる可能性があり、上記日数は**全システム共通の絶対的な最短日数ではない**。逆に認定が毎日でなければ実際はもっと長い。既存のEvidence typeと軸の実際の出現分布は未測定。特に恋愛Declarationだけを繰り返す場合、点数は進まない。

## 設計上の結論（まだ採用決定ではない）

- **20/50/80という仮閾値は成長実感に対して高すぎる可能性がある。** しかし成長を急ぐために加点係数を上げるとEvidence反復や恋人攻略ゲージ化を招く。実際のPattern成立頻度と分布を確認するまでは係数を変更しない。
- 長期5軸の値を「瞬間的な演技の唯一の根拠」にしない。正本の最近の会話・出来事から**直近Momentumに相当する背景**を導出できるかを先に調べる。推測で会話事実を作らない。
- 親密度6段階の成長速度と5軸の成長速度は別問題。親密度だけが進んで5軸が低い状態をどう演じるかは実機シナリオで確認が必要。
- **次の検証:** 実装済みのEpisode/Pattern/State読出し経路を確認し、Momentumを新規テーブルなしで導出できるか調査。合成履歴で「日常の気遣い」「深い相談」「仲直り」「非恋愛親友」「反復告白」を比較。実Geminiの費用発生は別承認。
