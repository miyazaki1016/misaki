# Misaki 料金階層・将来の成人向けモデル：対話決定ログ（2026-10-22）

> 本文はユーザーとの議論の最新状況を、決定／第一候補／保留／将来構想に分けた**設計記録**。料金・サービス内容を確約したものではない。既存の資料77・78や `docs/MISAKI_SYSTEM_VISION_20261021.md` を黙って上書きせず、変更理由と差分を明示する。現段階でmain、製品コード、本番美咲、本番Supabase、別事業アメふるには触れない。

## 1. 今回確認した実行優先順位【方向性合意】

1. **先に通常版Misakiを完成・磨き込む。** 美咲一人を優先し、会話品質、記憶、Persona Evolution、Relationship Story、自発メッセージの自然さ・安全性、外部情報選別とGemini軽量化を進める。第5次監査・第6次未検証ゲートを回避しない。
2. Free/Premiumのサービス設計と単位経済（1ユーザー・1成功会話・1自発通知あたりの総原価、課金転換率）を実測で検討する。**サービス開始時期・正式機能は未確定。**
3. **本格的な成人向け最上位プランは将来構想として保全し、当面の実装・GPU運用は見送る。** 一定の課金ユーザーと収益性が確認できた段階で、別モデル/自己ホスト可否と、法規・利用規約・年齢確認・決済・配信条件を改めて検証する。成人向け機能を現在のGeminiで提供できるとは扱わない。
4. 今設計する共有会話エンジンは**特定ベンダーに依存しないModelPort**を維持。成人向け実装のためにコアを分岐させず、外側でモデル利用許可・年齢/同意・契約・予算・利用ポリシーを管理する。モデルの違いが人格・記憶・関係の一貫性を損なわないかは後日独立評価。

## 2. Free/Premium自発メッセージ：過去文書と最新対話の差分【要仕様再確定】

### 保存済みの旧基本構想（資料 `MISAKI_SYSTEM_VISION_20261021.md` 第6章）
- Freeは美咲自身の日常・出来事・気持ちを中心にし、ユーザー過去会話／二人の思い出は自発話題に使わない。
- Premiumは本人許可のもとUser Memory・Shared Memoryの少数参照を検討。
- 料金プランは好意・愛情・Relationshipの強さと直結させない。

### 2026-10-22対話で掘り起こしたが原記録未確認の仕様候補
- **案A**：Freeは美咲の発信＋誕生日・年齢・居住地・職業などUser Profile記憶、Premiumはさらに二人の共有思い出。
- **案B**：Freeは美咲の発信が中心でUser Profile記憶の自発活用は時々のPremium体験版、Shared MemoryはPremium限定。
- **案C（最新の有力案）**：FreeにもUser ProfileとShared Memoryの自発活用を開放し、Premiumとの差は自発メッセージ量・高度な検索/付加機能。**ユーザーから「Freeにも記憶を開放した方がいいかな？」という検討問いがあり、アシスタントが案Cを第一候補として提案。ユーザーによる最終決定ではない。**
- **写真付き自発メッセージをPremium機能にする**というユーザー発案。アシスタント賛同。ただし正式仕様/写真保有・ダウングレード後の閲覧・通知回数等は未決。
- 以上は記憶を過去に確定済みと断定せず、**相互に競合する案と変遷**として保全する。旧資料77/78のFree memoryScopeは旧基本構想対応のままで、最新候補Cの採否が決まれば契約を改訂する。

### 料金と人格の不変条件
- どの案でも関係の成熟、思い出の保存、人格の変化を「課金すると親密度アップ」「解約したから関係悪化」に直結させない。
- 参照権限と保存/削除・Forgetは独立。ユーザーの合意、用途限定、失効世代、更新時の再評価を守る。
- 成人向け機能の許容範囲は、Relationship Engineの親密さそのものやユーザーの支払額とは区別した別の安全・コンテンツポリシー。

## 3. 成人向け最上位：なぜ当面見送るか【確定した優先順位／未実装】

- ユーザーは将来の**本格成人向け会話（軽い恋愛表現に限定しない）**を最上位プランとして検討したい意向。
- DeepSeekやQwenのような**公開ウェイトを自己ホストする案**を検討。公式APIの利用規約と公開モデルの重みライセンスは別契約。ライセンスに商用利用権があっても、成人向け商用配信の合法性・ホスティング・決済・App Store審査通過を保証しない。
- 大型DeepSeek本体は高メモリ/高費用。Qwen 8B/14Bや小型蒸留モデルは**比較試験候補**であり、日本語での長期人格保持・性的会話への適合性は未検証。GPU価格は動的であり、前チャットの見積は事業計画の確定原価ではない。
- 課金ユーザーが十分につくまで、専用GPUの月次維持費、成人向け専用モデルの学習・評価・配信開発への支出を**今はしない**。
- 将来検討時はモデルライセンス原本、モデル配布者/サービス提供者の条件、GPU事業者・決済・アプリ/ウェブ配信条件、適法な成人確認・同意と未成年保護、端末内/サーバログのプライバシーを別々に審査する。

## 4. 共有エンジン設計への確定要求

- `ModelPort` はprovider/model/availability/call-budget/response contractを抽象化。ベンダーを変えたら人格・記憶・関係の正本が変わる設計は避ける。
- **Content Policy（表現許容範囲）／Relationship（誰とどういう関係か）／Behavior（そのキャラの選択）／Entitlements（契約上利用できる機能）**を独立させる。年齢/同意/地域法令/プラットフォームポリシーの検査を拡張可能にする。ただし安全制御の回避機構は作らない。
- 将来の成人向けモデルは**未接続**。現在の共通エンジン要件は通常会話・Lab・自発メッセージの同等性、長期成長、記憶スコープ、選択的外部情報、節減の実測を優先する。
- 自発メッセージに写真を添付する場合、メッセージに自然な理由が先にあり、画像は付随する候補。Premium権限・写真利用権・同意・既存の配信安全条件は最終Coordinatorが再確認。
