# 美咲 会話育成実験室 — 実装入口と初回実験計画（2026-10-15）

## 目的と現在地
美咲の人格・会話品質は、実際の Gemini 応答を観察し、反例を集め、調整する段階に未着手。既存の単体テスト・プロンプト差分・source audit は**会話品質の実測ではない**。仕組みの整合性改善と会話育成は並行する。

## ソースを確認した事実（main）
- `app/api/acting-lab/route.ts` は既に開発用の演技研究室。Supabase クライアントを作らず、`VERCEL_ENV=production` では 404、`GEMINI_API_KEY` がなければ 500。
- 同 API は `createRelationshipActingGuide` と `createFallbackPersonaPrompt("chat")` を `generateGeminiJson` に渡し、指定 message を各関係 profile に**単発**送信する。モデルは `gemini-3.1-flash-lite`。
- `lib/gemini-json-generator.ts` は `contents` で履歴を受け取れるが、現行 acting-lab は `contents: []` 固定。複数往復の AI ユーザー、評価役、会話ログ保存、実運用チャットと同一のプロンプト構成は未実装。
- acting-lab は共有 fallback persona を使う**部分再現**であり、`app/api/chat/route.ts` の正本状態・記憶・行動・感情等を完全再現していない。acting-lab で良好でも本番品質の証明にはならない。
- Gemini API 呼び出しは課金の可能性があり、ユーザー承認前に実行しない。

## 作業順序
1. **安全な実験境界**：本番の chat API を自動会話に使用しない。正本・親密度・記憶・Body Clock・利用回数を書き換えない。開発環境のみ。実験ログはユーザーの実会話と分離し、機密情報を投入しない。
2. **現状の素の会話を観察**：人格と感情・関係性条件を固定。最初は人間が書いたシナリオを使う。AI ユーザー役を導入する前に、美咲の返答そのものを確認する。
3. **多角的なケース**：短文／長文、無口／饒舌、冗談、落ち込み、怒り、日常の雑談、仕事、記憶参照、誤解、沈黙、仲直り、恋愛への誘い、境界尊重。単発・5往復・20往復を分ける。
4. **評価**：文脈追従、自然さ、人格一貫性、会話の主導性、押し付け・質問連打、事実・記憶の捏造、距離感、反復、ユーザーがまた話したくなるか。自動採点は仮説、人間レビューを正本とする。
5. **チューニング**：原文とモデル・プロンプト版・シナリオ・設定を記録し、問題ごとに原因と変更を一対一で追跡。改善前後を同じ条件で比較。良かった返答の退行も確認。
6. **次段階**：素の会話が一定水準になった後、感情・行動状態を固定比較し、さらに5軸・交際状態・親密度を変える。状態の差が自然に言葉へ反映されるかを見る。

## 初回実行前の必須ゲート
- 実験入口の認証・公開範囲、課金上限、1実行のモデル呼び出し数、リトライによる上振れ、ログ保管場所を確認。
- 現行 acting-lab は開発環境でキーがあれば API を呼べる。**production 以外なら誰でも呼べるかもしれないため、認証・レート制限を確認するまで自動化・公開しない。**
- 現時点で**実 Gemini 会話の取得、AI 同士の対話、会話品質採点は未実施**。費用が発生する実行はせいちゃんの了承を得てから。
- 最初の実装優先度は acting-lab の認証・回数制限と、履歴を含む複数往復を安全に行う隔離実験 runner。既存 `generateGeminiJson` の履歴対応を再利用し、正本 DB を触らない。
