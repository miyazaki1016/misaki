## 当時の説明・結論（原文。作者の主張と実測を区別）

```text
Production Evidence boundary testing exposed an older failed turn blocking later canonical processing. The Analyzer can emit neutral polarity 0 once the invalid numeric enum is removed, while the internal contract correctly rejects anything except ±1.

This fix keeps the internal Evidence/DB contract unchanged and changes only the Gemini transport representation:
- Gemini responseSchema uses polarity as STRING enum ["-1","1"]
- received "-1"/"1" is normalized immediately to numeric -1/1
- existing parseEvidence() remains the authoritative fail-closed ±1 validator
- ordinary chat, DB, lease, retry, state, critical validator contracts are unchanged

Tests verify:
- request schema sent to Gemini uses the string enum
- valid transport value normalizes to numeric polarity
- out-of-contract "0" still fails closed

This should avoid both the previous Google 400 and neutral polarity poisoning.
```
