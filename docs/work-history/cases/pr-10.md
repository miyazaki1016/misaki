## 当時の説明・結論（原文。作者の主張と実測を区別）

```text
チャットproxyがGemini JSON parse 500時にbase route全体を再呼び出していたため、1回のユーザー送信で `consume_daily_message` が別request idで2回実行され得る経路を除去します。

base route内部の生成再試行はusage消費後に同一POST内で行われるため維持し、proxyからbase routeを呼ぶ回数を1回に限定します。

`Load failed` のクライアント表示修正は、この安全化の後に続けます。
```
