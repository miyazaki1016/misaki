## 当時の説明・結論（原文。作者の主張と実測を区別）

```text
匿名利用中に Safari 側で認証イベントが一時的に SIGNED_OUT / 匿名ユーザー差し替えになった場合、これまでの guard は会話キャッシュを消してページ再読み込みしていました。

実機で「送信中の入力バブルが消え、返答が出ない」現象が再現し、当該送信は server 側で usage まで処理済みだったため、匿名セッションの一時切断時にブラウザ会話を保持するよう修正します。

変更:
- 匿名 SIGNED_OUT は cache clear + reload せず、匿名再認証を試みる
- 匿名ユーザーIDが同一ブラウザ内で差し替わった場合は、会話を保持して owner だけ付け替える
- 恒久アカウントの SIGNED_OUT は従来どおり clear + reload
- 明示ログアウトは account/page.tsx 側の clear + navigation を維持
- 匿名の一時切断/差し替えで会話が消えないテストを追加

補足:
ローカル node test は実行環境から github.com のDNS解決ができず未実行。Vercel Preview build で型/ビルドを確認します。
```
