## 当時の説明・結論（原文。作者の主張と実測を区別）

```text
## What
- refresh `get_daily_message_usage` whenever permanent conversation history is canonically refreshed
- dispatch the refreshed usage to the chat page
- update remaining free count and free-limit input state without restoring 5-second polling

## Why
Real-device Chrome/Safari testing showed canonical conversation history converging across browsers while the remaining-count label and input enabled state could stay stale. Server-side quota enforcement still blocked the extra send, but the stale browser briefly accepted an optimistic bubble before rejection.

## Scope
This PR only fixes cross-browser quota UI convergence. It does not change the 20/day server enforcement, history retention, the 60-message display limit, or add polling.
```
