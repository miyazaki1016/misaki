調律設定が美咲共通の場合、本番適用した版が悪ければ影響が全ユーザーに一斉に出ます。下書き／適用の分離とロールバックだけでは不十分で、次を決めてください。

## 2. 調律の変更履歴そのものも仮名化・最小化の対象にする

共通材料契約では「生IDや生会話を監査ログへ無制限に残さない」とありますが、調律側の履歴（誰が・いつ・何を変えたか）も同じ扱いにしてください。設定値の履歴は運用者の行動記録であり、選別の監査エンベロープと同じく、保存するなら仮名化と保存期間の設計が先、が原則です。あわせて、調律値そのものにユーザーやキャラを特定できる内容（特定ユーザー向けの例外設定など）を持たせないことを、契約側の禁止事項として明記してください。

## 2. 発話意図の責任と Gemini の裁量境界

境界は「Gemini は、選別済み材料と発話意図に**含まれない事実・評価・約束を新たに導入しない**」と定義するのが検証可能でよいと考えます。語順や言い回しの選択といった表現上の裁量は残りますが、それは意図の変更ではなく言語化の範囲であり、残余のリスクは次の送信前検査で受ける、という整理です。

## 3. 送信前検査の責任者とフォールバック（最重要）

- **検査は生成したモデル自身に自己採点させない。** 同一モデル・同一経路の自己評価は、誤りを相関して見逃します。

- 意味的な検査（ニュアンスの逸脱など）を別モデルやヒューリスティクスで行う場合は「保証ではなく信号」として扱い、判定結果を記録に残す。

## 問1：通常復元がターン処理中に入った場合、どの境界で確認すべきか

確認境界は2か所で、役割が違います。

**（a）書き込み側の境界＝復元操作そのもの。** 通常復元が書き換えてよいのは（キャラ，範囲）に対する承認版ポインタ1件だけです。受入条件は「復元前後で、生存中セッションの固定レコードと処理中ターンの handoff が1バイトも変わらないこと」。復元がセッションやターンに触れる実装は、この時点で不合格にできます。

**（b）読み出し側の境界＝ターンの送信前ガード（独立ガードの判定点）。** 固定済み設定と、そのターンに結び付いた沈黙・質問不可の判定が同時に見えるのはここだけです。この境界では：
- 調律はセッションの固定レコード（キャラ，版，digest）から読む。承認版ポインタを読み直したら、その時点で不合格（復元の影響が漏れている）。
- 意図と質問可否はターンの snapshot 束縛から読む。復元はどちらにも影響しないはずで、影響していたら（a）か（b）の実装が契約違反です。
- ターンの監査記録に、固定版と意図の両方が残ること。後から「そのターンは復元前の版で、沈黙判定で止まった」と答え合わせできることが、両立の証拠になります。

セッション単位の確認では粗すぎ（復元はポインタを正当に変える）、復元操作の側で生存ターンを検査するのは境界の取り違えです。

## 問2：通常復元と緊急失効を区別するために必要な合成ケースと、先に決める仕様

区別の本質は「既存セッションに触れるか」です。通常復元は触れない、緊急失効は固定済みの版そのものを無効にする。必要なケース：

1. **生存セッションが固定中の版を、ターン処理中（意図決定後・送信前）に失効** → そのターンの送信は 0 件（通常復元との対照ケース）。モデル出力も定型文も出ないことが期待値。
2. **セッションが固定していない版の失効**（例：固定は C、失効は B）→ セッションは無影響。失効が対象を絞れることの確認。
3. **セッション作成の競合中に失効** → 失効した版を固定した新規セッションができないこと。
4. **失効済みの版への復元** → 拒否（未確認版への復元拒否の拡張）。
5. **ガードの再生成ループ中の失効** → 失効した版の下では定型文フォールバックもしない（停止）。定型文を許すかは下記の仕様決定に従う。
6. **同一（キャラ，範囲）への復元と失効の同時発行** → 最終状態がどちらか一方に確定し、監査で判別できること（混在・両方適用は不合格）。

これらの期待値を書く前に決める必要がある仕様（決まらないとケース1・5の期待値が書けません）：
- 失効の発動権限と、記録付き承認が要るか（本番適用と同格か）。
- 「停止」の意味：ターン途中での即時中断か、現ターン完了後の停止か。利用者に何か見せるか（無言か、固定の通知文か）。
- 失効の単位：（キャラ，範囲）か、版の全体か。
- 失効時のフォールバック：定型文を許すか（沈黙意図では既に「送らない」で確定済み。それ以外の意図について）。
- 監査記録で復元と失効を判別する項目（理由・操作者・対象版・影響セッション数）。

一方、**今回決めなくてよいもの**：再開方針の詳細、保持期間、正常判定の観察期間と閾値。ケース側は「適用後確認済みの版」を fixture の状態として与えれば書けます。その状態がどう作られるかは別途の決定であり、試験の前提に紛れ込ませないでください。

## 問3：次に着手できる最小の隔離試験（1件）

**「通常復元が沈黙ターンの途中で入っても、そのターンは沈黙のまま終わる」**

既存の fixture 同士の接続だけで組めます（#221 の復元構成 7054184729 と、統合側の沈黙ガード §108 の再利用）。未決の仕様（失効・TTL・閾値・再開）は一切必要としません。

構成：キャラ C、承認版ポインタ＝版 C（復元先として確認済みの版 A も用意）。セッション S は版 C とその digest を固定済み。ターン T は意図＝沈黙・質問不可の handoff を持つ。
手順：T の意図決定まで進める → 通常復元（ポインタ C→A）を割り込ませる → T を沈黙ガード経路に通す。

1. T のモデル呼び出し 0 件・送信 0 件（沈黙が復元に影響されていない）。
2. 復元後も T 完了後も、S の固定は（版 C，digest）のまま。復元後に作った新規セッションは A を固定する（復元が効くべき所には効いている）。
3. T の監査記録（試験側）に tuningVersion＝C と意図＝沈黙の両方が残る。
4. 対照：意図を通常回答に変えた同構成では、モデル呼び出し 1 件・送信 1 件で、設定は C のまま（0/0 が沈黙によるもので、復元でターンが壊れたのではないことの証明）。
