## 当時の説明・結論（原文。作者の主張と実測を区別）

```text
Production実機で 2026-10-02 21:37 JST に Gemini initial fetch が30秒で GEMINI_TIMEOUT となり chat 500 になったための最小修正。

- 429/502/503/504 の既存 bounded retry は維持
- 30秒 AbortError は2秒待って1回だけ再試行
- 2回目もtimeoutなら既存の error/refund path へ落とす
- 通常500はretryしない
- clientの false busy timer は復活させない
- regression contract追加
```
