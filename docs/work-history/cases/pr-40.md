## 当時の説明・結論（原文。作者の主張と実測を区別）

```text
Gemini の一時的な 429/502/503/504 を同一チャットリクエスト内で 2秒→5秒の最大2回だけ自動再試行します。通常の500や認証/設定系エラーは再試行しません。

UIは応答が1.8秒を超えた場合だけ「美咲ちゃん、ちょっと忙しそう…🤭 少し待ってね」を表示し、完了時に自動で消します。

既存の requestId / usage consume / canonical commit の外側で新しいチャット要求を作らず、再試行は同一 generateReply 内に閉じるため、再試行ごとの使用回数消費・関係ポイント加算・会話保存は発生しません。

回帰テストとして transient status/delay と待機表示の存在・解除を固定しました。
```
