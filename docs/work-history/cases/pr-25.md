## 当時の説明・結論（原文。作者の主張と実測を区別）

```text
匿名実機テストで、特定入力時に送信はサーバーまで到達して利用回数も消費される一方、Gemini返答待ちのまま「・・・」が続き、最終的に返答が出ないケースが再現しました。

変更:
- Gemini generateContent fetch に20秒の明示タイムアウトを追加
- タイムアウト時は例外として既存の catch に戻し、既存の refund_daily_message で利用回数を返却
- 初回/意味的リトライ、HTTP status、所要時間をログ
- 入力本文はログせず、messageLength / codePointLength / supplementary Unicode 有無のみ記録
- 特定の絵文字を原因と断定せず、次回実機再現時に比較できる情報だけ残す

これにより、外部APIがハングしてもVercel側の長いタイムアウトまで待たず、クライアントへエラーを返して入力中表示を終了できます。
```
