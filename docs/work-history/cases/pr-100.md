+# 美咲：匿名24時間・登録後長期記憶／Gemini軽量化の実装設計（2026-10-30）
+
+## 決定したユーザー仕様（未実装）
+- 匿名：**個々の情報が作成された時刻から24時間**で失効。新しい会話やトークン再発行で古い情報の期限を延長しない。
+- 匿名：会話履歴の画面表示は端末側で継続可能。ただし美咲の推論・自発発話・関係性判断に使用できる履歴は各発言の作成から24時間以内に限定する。
+- メール登録：長期記憶・過去履歴・関係性をアカウントに保持。登録時に失効済みの匿名記憶や履歴由来の知識を復活させない。登録後の履歴閲覧範囲と記憶への取り込みは別管理。
+- 明示的な削除は履歴・記憶・要約・関係イベント・Body Clockからも復活させない。
+
+## main監査（実装前）
+- `lib/canonical-state.ts` の `sealTemporaryState` は **トークン全体**を `Date.now()+24h` で封印する。これは情報ごとの24時間ではない。`app/api/persona/history/route.ts` の匿名 load はトークンを再封印し得る。
+- `app/api/chat/route.ts` は `rootState.memory` / `rootState.history` を読み、最大60履歴・最大30記憶をGemini文脈に使用する。現状、匿名の各記憶・履歴について独立した24時間フィルタがない。
+- `RootState.memory` は文字列配列。既存のライフファクトやプロフィール記憶にタイムスタンプを後付けせず、別の時刻メタデータを持つ後方互換移行が必要。
+- `temporaryRelationship`、`relationshipEngine`、Body Clock、自発発話、メール保存の経路も時間境界の対象。チャットrouteだけをフィルタして完了とはしない。
+- `app/chat/page.tsx` の端末キャッシュは表示用。期限切れの履歴をサーバーへ送って推論用に復活させない。
+
+## 実装の順序と受け入れ基準
+1. **時刻付き記憶スキーマ**：情報ID・作成時刻・最終編集時刻・失効時刻・削除墓標を設計。既存匿名状態は無期限の記憶として扱わず、移行方針を明示。登録ユーザーの既存永続データは変更しない。
+2. **単一の期限判定関数**：信頼できるサーバー時刻を使用。24時間ちょうどで失効。再会話・load・token refresh・Body Clockで元の失効時刻を延長しない。端末時計を信頼しない。
+3. **全読取境界で適用**：通常チャット、記憶の想起、life facts、Relationship Engine、Body Clock、メール保存、履歴同期。履歴の画面表示とAI文脈の参照を分離。
+4. **メール保存の原子性**：有効情報だけを永続側へ移し、期限切れ・削除済み情報を移さない。メール確認待ち中の追加会話と再試行・二重保存も検証。
+5. **回帰テスト**：23:59:59有効／24:00:00失効、別時刻の複数情報、再会話で延命しない、端末履歴は表示できるがAIには渡らない、削除が復活しない、Safari匿名ID交換、メール保存境界、Body Clock、自発発話、登録ユーザー無変更。
+6. **段階的リリース**：まずテストと隔離実装、CI合格、Preview、匿名/登録の実機確認後にmainへ。現時点では本番変更なし。
+
