## 当時の説明・結論（原文。作者の主張と実測を区別）

```text
Relationship AnalyzerのGemini呼び出しがHTTP失敗／text欠落でunavailableになる際、Googleのエラー原因が失われるため、一時診断ログへstatusとGoogle API error.code/error.messageだけを記録します。Evidence Analyzerと同じファイルのcritical validatorの失敗だけが対象です。APIキー・本文・レスポンス全文・error.detailsは出さず、error.messageに既知のキー／会話文が含まれる場合もraw/JSON-escaped表現を伏せます。成功時はログを出しません。

responseSchemaのpolarity.enum=[-1,1]は変更していません。今回の目的は実エラーの取得であり、400原因の確定やschema修正は含みません。通常チャット/shared generator、DB、lease、retry（10秒・retryなし）、既存の例外メッセージを維持します。原因調査後に取り除く診断変更です。

変更ファイル：lib/relationship-analyzer-v1.ts、tests/relationship-analyzer-diagnostics.test.cjs。

検証：既存249＋追加7＝256/256成功、TypeScript、production build、git diff --check成功。追加ケースはHTTP失敗、text=null、異常errorフィールド、秘密情報の伏せ、成功時無ログ、critical失敗／成功を確認します。

GitHub CIはPR起点のため、同じ検証をローカルで成功させた後にDraft PRを作成しました。commit `42177230a0a3c8926689499ffb19de4f1044d8d7` の[GitHub CI #321](https://github.com/miyazaki1016/misaki/actions/runs/37119991574)もcompleted/successです。merge・環境設定変更・DB変更は行っていません。
```
