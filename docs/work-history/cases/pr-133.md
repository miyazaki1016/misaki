+### Misakiの設計原則（再確認）
+
+1. **事実は共有できても、想い出の解釈はそれぞれ違う。** 事実の記録とキャラクター別の感情・評価を独立させる。感情が薄れたり変化しても、出来事を捏造・改変しない。
+2. **「誰が知っているか」に加えて「誰との関係・どの場で知ったか」を保持する。** 所有者、character ID、参加/目撃、明示共有、会話/グループの出典、権限、期限を別々に検証する。異なるユーザーの個人情報は完全に分離。
+3. **記憶保存 ≠ 記憶想起。** 美咲が以前の話を毎回持ち出すのではなく、関連性・重要度・自然さ・頻度制限・秘密性を考慮して想起する。事実と推測を混同しない。
+4. **人格の核 ≠ 関係の成長。** 美咲自身の価値観を維持しつつ、相手との経験で距離感・感情・気遣いが変化する。
+5. **外部取り込み情報 ≠ 美咲と共有した想い出。** 将来移行機能を検討する場合、出典・話者・本人同意・取り込み候補の確認を必須とする。
+6. **「忘れる」は全参照経路で守る。** 匿名の情報別24時間上限、削除抑止、派生データ、再送、通知、復旧経路を迂回させない。競合動向を理由に安全条件を緩めない。

+## 2026-11-02 ChatGPT Work利用回数の節約（運用方針）
+
+> **目的**：Workの利用制限を踏まえ、**報告・再確認だけのWorkをできるだけ発生させず、実装が前進する単位でまとめて依頼する**。安全確認を省略する趣旨ではなく、確認を実作業へ組み込む運用変更である。
+
+1. **単純なReadOnly確認は原則として専用Workを起こさない。** GitHubのPR・CI・SHA・既知の差分・Vercelの状態など、ソラ側の接続ツールで取得できる範囲はソラが直接確認し、職人さんのWorkを消費しない。
+2. **実装→必要最小限の照合→テスト→CI→（許可範囲内の）反映→結果報告を、可能な限り一度のWorkにまとめる。** 小さな確認だけを理由とした途中停止・再依頼・重複監査を避ける。
+3. **既に成功した検証を理由なく何度もやり直さない。** ソースや環境が変わった場合の影響範囲に絞り、必要な回帰検証は省略しない。
+4. **重要な操作の承認境界は維持する。** mainマージ/本番デプロイ、本番DB・migration・環境変数の変更、既存データの削除、実モデル送信、検証用書込みなどは、承認された範囲内でのみ実行。承認されていない次の工程には進まない。
+5. **問題がない場合は承認済み工程を連続実行し、最後に簡潔な結果を報告する。** ブロッカー・破壊的影響・承認範囲超過が生じた場合だけ停止して相談する。
+6. **他プロジェクトの担当範囲を重複調査しない。** Misaki・アメふるの自動棚卸し/開発台帳更新/イベント駆動自動化は独立プロジェクトが担当。Misaki本体では本体のマージ/デプロイへの影響だけ確認する。
+
+**指示作成時の原則**：ソラは「確認だけのWork」より「具体的な完成条件を持ったWork」を優先し、同じ質問・同じ監査をユーザーに繰り返させない。最終判断に必要な事実と未検証項目は正確に区別する。
